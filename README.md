# 画像アップローダー（入稿データ受付アプリ）

お客さんがスマホで作った画像を、**圧縮されないまま原寸で**受け取るためのアプリです。
LINE で送ってもらうと画像が縮んでしまう問題を解消し、あわせて
タペストリー / ポスター / ステッカーの **入稿データ（塗り足し付き）を自動で書き出します**。

---

## できること

**お客さん側（スマホ）**

1. 3枚のアニメーション付きの説明（元ファイルを送ってほしい理由、塗り足しとは何か）
2. **STEP 1** 画像かPDFを選ぶ → その場で解像度を読み取り、小さすぎる画像・LINE経由の画像を警告
3. **STEP 2** 商品と仕上がりサイズを選ぶ → **サイズごとに「何dpi相当か」をその場で表示**。
   同じ画面で有料オプション（塗り足し作成＆高解像度化）を申し込め、ONにすると**出来上がる入稿データをその場で描いて見せる**
4. **STEP 3** 名前を入れて送信 → 受付番号が出る

アップロードは画像を選んだ瞬間に裏で始まるので、設定を選んでいる間に送信が終わります。
2MB ずつ分割して送り、途切れても自動で送り直して続きから再開するため、電波が不安定でも通ります。

**あなた側（`/admin`）**

- 受付一覧（画質判定・お客さんの指定内容・ご要望）
- 原本（無加工）／入稿データ／断裁位置ガイドのダウンロード
- 案件ごとの ZIP 一括ダウンロード

## 起動

```bash
cd image-intake
npm install --cache /tmp/npmcache
cp .env.local.example .env.local   # ADMIN_PASSWORD を必ず変更
npm run dev
```

- お客さん用: http://localhost:3210
- 管理画面:   http://localhost:3210/admin

本番として動かすときは、下の「本番公開」を参照（`npm run build:prod` → `npm run start:prod`、ポート 3300）。

### 環境変数

| 変数 | 意味 |
| --- | --- |
| `ADMIN_PASSWORD` | 管理画面のパスワード。**必ず長く推測されにくいものに変更してください** |
| `STORAGE_LOCAL_DIR` | 保存先フォルダ。未設定なら `image-intake/data` |
| `MAX_FILE_MB` | 1ファイルの上限（既定 200MB） |
| `BFL_API_KEY` | AI の描き足し（Black Forest Labs）。未設定なら描き足しは使えない |
| `CMYK_ICC_PROFILE` | CMYK 変換に使う ICC。未設定なら Adobe の Japan Color 2001 Coated |
| `UPSCAYL_MODEL` | Upscayl のモデル名（既定 upscayl-standard-4x） |

## 本番公開（このMacで動かし、固定URLで公開する）

お客さんに渡す URL は、この Mac で動いているアプリを **Cloudflare Tunnel** で公開します。
高画質化（Upscayl）・CMYK 変換・PDF プレビュー（sips）が Mac の上で動くので、クラウドには載せずこの形にしています。
お客さんの画像はこの Mac の `data/` に保存され、GitHub には含まれません（`.gitignore`）。

### 最初に一度だけ（ご自身で行う操作）

1. Cloudflare の無料アカウントを作り、使いたい独自ドメインを Cloudflare に追加する
2. ターミナルで `cloudflared tunnel login` を実行し、開いたブラウザでドメインを選んで許可する

### トンネルと自動起動の設定

```bash
cd image-intake
npm install --cache /tmp/npmcache
cp .env.local.example .env.local            # ADMIN_PASSWORD と API キーを設定
npm run build:prod
cloudflared tunnel create image-intake       # 表示されるトンネル ID を控える
cloudflared tunnel route dns image-intake upload.example.com   # お客さんに渡すホスト名
cp deploy/cloudflared-config.example.yml ~/.cloudflared/config.yml   # <TUNNEL_ID> などを書き換える
```

ログイン時に自動で起動し、落ちたら立ち上げ直す設定（launchd）:

```bash
sed "s#<APP_DIR>#$PWD#g" deploy/launchd/com.image-intake.web.plist.example > ~/Library/LaunchAgents/com.image-intake.web.plist
cp deploy/launchd/com.image-intake.tunnel.plist.example ~/Library/LaunchAgents/com.image-intake.tunnel.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.image-intake.web.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.image-intake.tunnel.plist
```

### アプリを更新したとき

```bash
npm run build:prod
launchctl kickstart -k gui/$(id -u)/com.image-intake.web
```

### 注意

- **Mac がスリープすると繋がらなくなります。** `deploy/start-production.sh` は起動中だけ `caffeinate` でスリープを止めます。ふたを閉じて使うなら電源につないでください
- 本番（ポート 3300）と開発用の `npm run dev`（ポート 3210）は同時に動かせます。ビルド先が別（`.next-prod` / `.next`）なので互いに壊しません。保存先の `data/` は共通です
- 管理画面 `/admin` もインターネットから開けます。同じ接続元からログインに 15分で10回失敗すると、しばらく受け付けません
- 同じ Wi-Fi 内だけで試すなら `http://<MacのIP>:3210` でも開けます
- LINE のアプリ内ブラウザで開かれた場合は、写真が選べない端末向けの案内が自動で表示されます

## 保存されるもの

`data/orders/<受付番号>/` に、案件ごとにまとまって入ります。

| ファイル | 中身 |
| --- | --- |
| `original.*` | **お客さんが送った原本。一切加工していません** |
| `print_<幅>x<高>px_<dpi>dpi_bleed<px>.png` | 入稿データ（指定サイズ＋塗り足し込み、dpi情報を埋め込み済み） |
| `guide.jpg` | 断裁位置を赤い破線で示した確認用画像 |
| `preview.jpg` | 一覧表示用の縮小画像 |
| `order.json` | 受付内容すべて（お客さんの指定・判定結果・寸法） |

5000万画素を超える大判は、PNG だと重すぎるため JPEG（品質95・4:4:4）で書き出します。

## 画質判定の考えかた

「その仕上がりサイズで刷ると何dpi相当になるか」を計算し、商品ごとの基準と比べています。
基準は `src/lib/products.ts` の `idealDpi` / `minDpi` で、**ここを書き換えれば判定も表示も追従します**。

| 商品 | 書き出しdpi | きれい | 最低限 | 標準の塗り足し | サイズ |
| --- | --- | --- | --- | --- | --- |
| タペストリー | 150 | 150 | 100 | 10mm | 1000×2100 / 1000×2300 / 1000×2400 mm |
| ポスター | 300 | 200 | 120 | 3mm | A3 / A2 / **A1（標準）** |
| ステッカー | 350 | 300 | 200 | 3mm | 50 / 70 / 100 角ほか |

初期選択は各商品の `defaultSizeId` で決まります。

サイズを増やす・減らすのも同じファイルの `sizes` を編集するだけです。
プリセットは**縦向きで書いておけば**、横向きは画面側で自動的に入れ替わります。

## 塗り足しの作りかた

原本には絶対に手を加えず、常に別ファイルとして書き出します。

- **全面に広げる（cover）**: 塗り足しまで含めた紙面を絵柄で埋めます。塗り足し部分にも本物の絵柄が入るので、断裁がずれても白フチが出ません。印刷所の標準的なやりかたです。
- **全体を入れる（contain）**: 絵柄を切らずに収め、まわりを「鏡ばり／端の色を延長／指定色」で埋めます。
  絵柄と仕上がりの縦横比が大きく違うときは鏡ばりだと絵が二重に見えるため、
  アプリが自動で「指定色」をおすすめし、その場のプレビューで見比べられるようにしてあります。

背景が透明な PNG は、指定された下地色を敷いてから書き出します（印刷では透明を表現できないため）。

## 有料オプション（塗り足し作成 ＆ 高解像度化）

`src/lib/products.ts` の `OPTION_PRICE_YEN` / `OPTION_LABEL` で定義。現在 **¥5,000（税別）**。

- **ONのときだけ**入稿データを生成します。OFFなら原本とサムネイルだけを保管します。
- 受付一覧では申込み案件にバッジが付き、`order.json` の `optionPriceYen` に金額が残ります。
- **高解像度化の中身**: lanczos3 で指定サイズまで拡大し、拡大率1.2倍超のときだけ控えめなシャープをかけています。
  情報を増やす生成AI的なアップスケールではないので、2.1mのタペストリーに1000px級の画像といった
  極端なケースでは眠い仕上がりになります。そこは Topaz などの外部ツールで別途処理する前提です。

## PDF について

PDFも受け取れます。ベクターデータなので扱いを分けています。

- pdf-lib で1ページ目の紙面サイズだけ読み取り、`order.json` に mm 換算できる形で残します
- dpi判定は行いません（画素数の概念がないため）
- 入稿データの自動生成は行わず、`要手作業` として受付だけ通します

---

## トンボ付きPDFは CMYK です

Acrobat / Illustrator で「RGB と CMYK が混在」と警告が出ないよう、PDF 全体を CMYK で統一しています。

- 画像は **Japan Color 2001 Coated**（Adobe アプリに同梱の ICC）で CMYK に変換して埋め込み
  - 変換のレンダリングインテントは「知覚的」。彩度の高い AI 画像でも色を潰さず、階調を保ったまま CMYK に収めます
  - 別の印刷条件にしたいときは `.env.local` の `CMYK_ICC_PROFILE` に ICC のパスを指定
- トンボはレジストレーション（CMYK 各100%）
- **出力インテント**（どの印刷条件の CMYK か）と、**TrimBox / BleedBox**（仕上がり枠・塗り足し枠）を PDF に書き込み済み。印刷所のプリフライトがそのまま読めます
- `print_…px….png/jpg` は **RGB マスター**（Photoshop で追加調整するとき用。CMYK 変換前の状態）

> 鮮やかな青・シアン・ネオン系は、CMYK の色域の外なので変換でくすみます（印刷の物理的な限界で、ツールの問題ではありません）。
> 気になる色がある場合は RGB マスターを Photoshop で開き、色を詰めてから書き出してください。

## 管理画面の「仕上げの調整」（オプションの範囲）

オプション申し込みのある案件を開くと、下に調整パネルが出ます。**お客さんの指定はそのまま残し、入稿データだけを作り直します。**

| 項目 | できること |
| --- | --- |
| 商品・仕上がりサイズ | 別のサイズ・向き・mm 指定に変更 |
| 比率の合わせかた | **トリミング**（残す位置をプレビューのクリック／9マス／スライダーで指定）<br>**余白で埋める**（鏡ばり・端を伸ばす・指定色）<br>**AIで描き足す**（下記） |
| 塗り足し | 0〜30mm |

「この設定で作り直す」を押すと裏で再生成し、前回のデータは差し替わります。

## AI で比率に合わせて描き足す（任意・外部API）

比率が合わないとき、切ったり余白を付けたりせず **絵柄の続きを AI に描かせる** 機能です。
Black Forest Labs の **FLUX Outpainting** を使います。

1. https://dashboard.bfl.ai でアカウントを作り、API キーを発行
2. `.env.local` に `BFL_API_KEY=発行したキー` を追記して `npm run dev` を再起動

仕組み（画質を落とさないための工夫）:

- BFL の出力は最大 4MP で、印刷サイズには足りません
- そこで **足りない外側だけ** を AI に描かせ → Upscayl で拡大して背景にし → **中央には原本（高解像度化済み）を貼り戻し**、境目をぼかして馴染ませます
- つまり AI が作るのは描き足した部分だけで、元の絵柄の画質はそのまま

AI で広げるのは **微調整の範囲だけ** です:

- 判定は「仕上がりサイズの中で、原本の絵柄が占める割合」（`products.ts` の `artCoverage`）
- **70% 以上**（`AI_EXPAND_MIN_COVERAGE`）なら自動で描き足します。例：2:3 の画像 → タペストリー 1000×2100mm は 71%
- **70% 未満**は大きな再レイアウトとみなし、**描き足しも高画質化もせず原本のまま預かります**。管理画面に「再レイアウト（手作業）」と出ます。例：2:3 のチラシ → 1000×2400mm は 63%
  - 文字の多いチラシを細長くするような案件は、AI では商用品質にならないため（検証済み）。お客さんの画面には何も表示しません
  - 対象は「そのまま印刷」を選んだ案件だけ。「全体を入れる（周りに余白）」はお客さんが余白を選んでいるので、そのまま処理します
  - 管理画面で調整して作り直した場合は、あなたの判断を優先して処理します（「AIで描き足す」を選ぶと注意文が出ます）

注意:

- **お客さんの画像が BFL のサーバーへ送信されます。** 利用規約・お客さんへの説明は運用側で判断してください
- 1回ごとの従量課金です（単価は BFL のダッシュボードで確認してください）
- キー未設定のときは管理画面で選べないようになっています

## お客さんに見えるもの（再確認）

## オプションは2種類（各 ¥2,500・税別）

価格と説明文は `src/lib/products.ts` の `OPTIONS` だけで変えられます（画面・合計・管理画面に反映）。

| オプション | 生成されるもの |
| --- | --- |
| **塗り足し・トンボ作成** | 塗り足し付き RGB マスター ＋ トンボ付き CMYK PDF。**「そのまま印刷」の場合は切り取らず、中央に置いて足りない辺を描き足す**（AI） |
| **高画質化** | Upscayl で解像度を引き上げる。高画質化だけのときは **トンボなし・塗り足しなし** の CMYK PDF |
| 両方 | 高画質化した原本を中央に置き、足りない辺と塗り足しを描き足して、トンボ付き PDF |
| なし | 生成しない（原本のみ保管） |

お客さんの画面での振る舞い:

- 絵柄の入れかた = 「そのまま印刷」／「全体を入れる（周りに余白）」
- 解像度が足りないと「注意：キレイに印刷できない可能性があります（◯dpi相当）」
- **高画質化を ON にすると**、注意が緑の「高画質化して仕上げます」に変わり、サイズ一覧の赤丸も緑＋「※高画質化」になる
- **塗り足し・トンボ作成を ON にすると**、「そのまま印刷」の説明と仕上がりイメージが「切らずに描き足す」に変わる

> 「そのまま印刷」でオプションなしの場合、比率が合わない部分は切り落とす前提の表示です（描き足すのは有料オプションの価値として分けています）。

## AI 描き足しの API について

- 現在の実装は **Black Forest Labs の FLUX Outpainting**（`BFL_API_KEY`）
- キー未設定のときは、**絵柄は切らずに鏡ばりで仮に埋め、管理画面に「要手作業」と記録**します（Photoshop の生成拡張で仕上げる運用）

## 印刷費の見積もり（概算）

金額はすべて **`src/lib/pricing.ts` の1か所** にあります。書き換えると、お客さんの画面・確認画面・完了画面・管理画面の見積もりがすべて変わります。
金額は **税別で持ち、消費税10%は最後に別で乗せます**。見積もりはサーバー側でも計算し直して `order.json` に保存するので、ブラウザ側で金額を書き換えられても影響しません。

| 商品 | 印刷費（税別・1枚） | 状態 |
| --- | --- | --- |
| タペストリー 1000×2400 | ¥15,000 | **確定**（ここを基準に、ほかのサイズは面積で決まる） |
| タペストリー 1000×2100 / 1000×2300 | ¥13,200 / ¥14,400 | 面積から自動 |
| タペストリー 自由サイズ（例 1800×2600） | 面積から自動（例 ¥28,300）・下限 ¥5,000（仮） | 面積から自動 |
| ポスター A1（PP加工） | ¥3,500 | **確定** |
| ポスター A2 / A3 | ¥2,500 / ¥1,800 | 仮（要確認） |
| 自由サイズ | 基準サイズとの面積比 | 仮 |
| ステッカー | 枚数とサイズで段階単価（下記） | 仮（相場の中央値〜やや上） |

ステッカー（100mm角基準の1枚単価）:
1〜9枚 ¥450 ／ 10〜 ¥300 ／ 30〜 ¥220 ／ 50〜 ¥160 ／ 100〜 ¥120 ／ 300〜 ¥85。
サイズで係数（50mm角 0.6 〜 150mm 1.5）、印刷費の最低料金 ¥2,000。

お客さんが選ぶのは「仕上がり」と「形状」の2つ（`pricing.ts` の `STICKER_FINISHES` / `STICKER_SHAPES`）:

| 仕上がり | 金額 |
| --- | --- |
| **1シートに複数枚** | 無料。1シートに何枚並べるかは選ばせず、サイズや形に合わせてこちらで決める |
| **1枚ずつカット** | ＋¥30/枚 |

| 形状 | 金額 |
| --- | --- |
| **四角形** / **丸型** | 無料 |
| **自由カット** | ＋¥30/枚 |

枚数は常に「ステッカーの枚数」。有料の加工は見積もりに別の行で出ます（例：1枚ずつカット ¥30 × 30枚）。

データ加工オプション（塗り足し・トンボ作成 ¥2,500 / 高画質化 ¥2,500）は注文ごとに1回ぶん加算されます。

## 1回の注文で複数デザイン

- 画像は **まとめて最大20点** まで選べます（同時に3点ずつアップロード。大きな PDF の後ろで小さな画像が待たされない）
- アップロードは 2MB ずつ。途切れたら間隔を空けて最大10回まで送り直します。送り直す前にサーバーが受け取った位置を確認して続きから再開し、同じ部分が二重に届いても壊れません。失敗したデザインには「もう一度送る」ボタンが出ます
- PDF は pdf-lib で紙面サイズを読みます。開けない PDF（パスワード付きなど）でも受付は止めず、紙面サイズを本文から探して預かります
- **PDF の解像度判定**：1ページ目の描画命令を読み、埋め込み画像が紙面上に何pt で描かれているかと画素数から ppi を出します（`src/lib/pdfInspect.ts`）。紙面の15%以上を占める画像のうち一番低いものを使い、画像と同じ「注意／ぎりぎり／問題なし」を出します。画像が無い PDF は「ベクターデータ」、画像が小さいだけの PDF は「文字や図形が中心」と案内。画像入りの PDF は高画質化も申し込めます
- タペストリーの料金は `pricing.ts` の `tapestryPriceYen`。大判プリント専門店の3サイズの価格（100×210 / 100×240 / 180×260cm）の面積に対する伸び方を使い、1000×2400mm＝¥15,000 に合わせて全体を倍率調整しています
- **PDF のプレビュー**：送信完了時に、macOS 標準の `sips` で1ページ目を JPEG にします（`src/lib/pdfThumb.ts`、5MB で約1秒）。選択画面・仕上がりイメージ・確認・完了画面・管理画面に出ます。Mac 以外のサーバーでは「PDF」の表示のまま
- チャンクは XHR で 2MB ずつ送り、送信中に20秒進まない／送り終わって15秒返事が無いときは中断して、受け取り状況を聞いてから続けます（スマホ＋中継で返事だけが数分遅れる現象への対策）
- 商品（タペストリー／ポスター／ステッカー）は注文全体で1つ。**サイズ・枚数・絵柄の入れかた・オプションはデザインごと** に選べます。「この設定をほかの◯点にもコピー」あり
- **タペストリーは 1デザイン＝1枚**（枚数欄は出ません。サーバー側でも1に固定）
- 見積もりはデザインごとに出し、注文の合計は小計を足してから消費税を1回だけ計算します

保存のしかた:

- **1デザイン＝1案件** として保存します（生成・調整・ZIP・プレビューは今までの仕組みのまま）
- 同じ注文の案件は `groupId`（お客さんに伝える受付番号）で束ねます。案件番号は `受付番号-1`、`-2`…。1点だけの注文は受付番号そのまま
- 管理画面では受付番号ごとにまとめて表示し、注文の合計も出ます

オプションを付けたときの「仕上がりイメージ」は、空白部分を **同じ絵柄をぼかして広げた画像** で埋めて見せます（実際の生成結果ではなく、イメージです）。
